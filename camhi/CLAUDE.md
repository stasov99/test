# Контекст проекта для Claude на мини-ПК

Ты работаешь на домашнем мини-ПК пользователя: Windows 11 Pro + WSL2 (Ubuntu).
Цель — непрерывная запись 3 камер в высоком качестве на локальный диск, без облака.

## Что за камеры
- 3× PS-Link (Hichip, приложение CamHi), питание от сети, связь только 4G.
- У каждой своя SIM Yota: CGNAT, белого IP нет, входящие соединения невозможны.
- Аплинк 4–5 Мбит/с на камеру, тариф безлимитный.
- UID вида `SSAU-xxxxxx-xxxxx`: P2P семейства PPPP/CS2. RTSP/ONVIF снаружи недоступны.
- В меню камеры нет RTMP/Push. FTP шлёт только тревожные снимки. Есть Wi-Fi и SD.

## Выбранная схема (Путь A)
Вендорский клиент **HiP2P Client (Windows)** тянет поток по P2P и пишет на диск.
`recorder/rotate-local.sh` (из WSL) чистит архив по `RETENTION_DAYS`.
SD-карта в камере — резервная копия на объекте.
Подробности — в `README.md`, разделы 7–8.

## Текущий этап
1. Пробный запуск: добавить 3 камеры в HiP2P по UID, записать по 1–2 часа на
   встроенный диск и измерить реальный поток (ГБ/сутки), обрывы, переподключение.
2. По итогам выбрать размер диска (сейчас диска ещё нет).
3. Если HiP2P не справляется (обрывы, нет автопереподключения, неудобный
   формат, падения), пишем сторож: перезапуск клиента + проверка, что файлы
   растут. Если и этого мало — мост «P2P → локальный RTSP» (через SDK Hichip
   или реверс, заготовки в `frida/`), дальше ffmpeg/go2rtc/Frigate.

## Правила
- Только камеры пользователя. Никакого сканирования чужих UID или устройств.
- Пароли и UID храни в `recorder/cameras.env`, не коммить (файл в .gitignore).
- Windows-часть (планировщик, электропитание, HiP2P) настраивай через
  PowerShell (`powershell.exe` доступен из WSL), Linux-часть — через bash в WSL.
